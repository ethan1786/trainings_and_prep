Flow

1. Product reqs → 2. Facts/scale → 3. Constraints→Decisions → 4. Trace data path → 5. Failure modes

Product Reqs (write on board)

□ Snapshot on page load
□ Live deltas via WebSocket
□ Time window changes (1m/5m/1h/1d)
□ Stale flag when source is down
□ Pre-ranked default page
□ Custom watchlist (auth)

Numbers

Inbound10-15 exchanges, 1-2M ticks/sec peak
Outbound2M concurrent users
Assets20K displayed
WS/node100K connections → 20-30 nodes
CoalesceBatch per 250ms
Latency<1s tick-to-client, <100ms page load

Data Path

Exchanges→ Inbound WS (active-active)
→ Kafka (raw ticks)
→ Processing (dedup, aggregate, stale detect)
→ Redis (snapshot) + Kafka (deltas)
→ Outbound WS Gateways (coalesce, subscribe)
→ Clients

Failure Recovery

Inbound WSActive-active, dedup downstream
ProcessorRedis snapshot + Kafka replay
GatewayUsers reconnect, refetch HTTP snapshot
ExchangeHeartbeat → stale flag → propagate

Key Phrases

"Hard problem is fanout, not ingestion"
"Fanout is a scheduling problem, not a socket problem"
"HTTP is truth, WebSocket is optimization"
"Show stale, never pretend data is fresh"

DON'T FORGET

Coalescing: "Can I push everything to 2M users?" NO → batch per 250ms
Stale: heartbeat missing → mark flag → propagate to UI
